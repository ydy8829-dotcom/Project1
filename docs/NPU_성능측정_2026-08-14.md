# Furiosa NPU 기반 RAG 서비스 성능 측정

## 측정 목적

Furiosa NPU에서 실행 중인 Qwen3 생성 모델과 Reranker를 포함한 최종 RAG API의 종단간 응답 성능을 측정한다. 이후 동일 조건의 CPU·GPU 결과와 비교할 수 있도록 기준값을 확보한다.

## 측정 조건

- API: `http://127.0.0.1:8002`
- 생성 모델: `furiosa-ai/Qwen3-8B-FP8`
- Reranker: `furiosa-ai/Qwen3-Reranker-0.6B`
- NPU 배치: Qwen3 npu4~npu7, Reranker npu1
- 질문 수: 5개 질의를 순환하여 총 20회 측정
- 워밍업: 2회
- `top_k`: 5
- 측정 범위: FastAPI 요청부터 최종 답변 수신까지의 종단간 시간

## 결과

| 지표 | NPU 측정값 |
|---|---:|
| 성공률 | 100% (20/20) |
| 평균 응답시간 | 1.836초 |
| 최소 응답시간 | 0.083초 |
| 최대 응답시간 | 3.505초 |
| P95 응답시간 | 3.385초 |
| 처리량 | 0.545 requests/sec |
| 생성 토큰 처리량 | 56.591 tokens/sec |

## 해석

측정된 최종 NPU RAG 서비스는 20회 요청을 모두 성공적으로 처리했다. 평균 응답시간은 약 1.84초이며, 95%의 요청이 약 3.39초 이내에 완료됐다. 검색·Reranker·LLM 답변 생성을 포함한 실제 서비스 관점의 종단간 수치이므로, 단순 모델 추론시간과 구분한다.

## 전력소비 측정 계획

전력은 추론 중 NPU 서버에서 `furiosa-smi info`를 반복 실행하여 측정한다. 유휴 상태와 요청 처리 상태의 Power 값을 각각 기록하고 평균값과 피크값을 비교한다. 현재 실행환경에서는 원격 `furiosa-smi` 표본을 자동 수집하지 않았으므로 전력 수치는 아직 기입하지 않는다.

## CPU·GPU 비교 시 주의사항

CPU·GPU 비교는 동일 모델, 동일 질문, 동일 `max_tokens`, 동일 동시성 조건에서 측정해야 한다. 현재 결과만으로 NPU가 CPU·GPU보다 우수하다고 결론 내리지 않는다. 비교 환경이 확보되면 동일 벤치마크 스크립트로 재측정한다.

## 재현 명령
