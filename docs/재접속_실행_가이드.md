# Furiosa NPU + RAG 프로젝트 재접속 실행 가이드

이 문서는 노트북을 재부팅하거나 SSH 연결을 다시 시작한 뒤, Furiosa 서버와 반도체 공정장비 RAG 프로젝트를 재실행하기 위한 안내서입니다.

## 전체 포트 구조

```text
Furiosa 원격 Qwen3 서버: 8001
내 PC SSH 터널:          18001
내 PC FastAPI RAG:       8002
```

총 4개의 PowerShell 창을 사용합니다.

```text
1번 창: Furiosa 원격 서버 접속 및 모델 서버
2번 창: SSH 터널
3번 창: FastAPI RAG 서버
4번 창: 연결 확인 및 질문 테스트
```

---

## 1단계 — Furiosa 서버 접속 및 모델 서버 확인

새 PowerShell 창에서 입력합니다.

```powershell
ssh furiosa
```

정상 접속 시 다음과 비슷한 프롬프트가 나타납니다.

```text
root@edu-hanyang-3:~#
```

NPU 상태를 확인합니다.

```bash
furiosa-smi info
```

모델 서버가 이미 실행 중인지 확인합니다.

```bash
curl http://127.0.0.1:8001/v1/models
```

정상 결과 예시:

```json
{"object":"list","data":[{"id":"furiosa-ai/Qwen3-8B-FP8"}]}
```

모델 정보가 나오면 1단계 성공입니다. 이 창은 닫지 않습니다.

### 모델 서버가 실행 중이 아닐 때

`curl`에서 연결 오류가 나오면 서버를 시작합니다.

```bash
furiosa-llm serve furiosa-ai/Qwen3-8B-FP8 --port 8001
```

다음 로그가 자동으로 표시되면 정상입니다.

```text
Uvicorn running on http://0.0.0.0:8001
```

주의: 위 로그 문장은 직접 입력하는 명령어가 아닙니다.

### 1단계 오류 확인

```bash
furiosa-smi info
```

이 명령에서 NPU가 보이지 않으면 NPU 서버 또는 드라이버 상태를 관리자에게 확인해야 합니다.

```bash
which furiosa-llm
furiosa-llm version
```

`furiosa-llm: command not found`가 나오면 Furiosa 실행 환경이 로드되지 않은 상태입니다.

## 2단계 — SSH 터널 연결

새 PowerShell 창을 열고 입력합니다.

```powershell
ssh -N -L 18001:127.0.0.1:8001 furiosa
```

아무 메시지 없이 커서가 멈춘 것처럼 보이면 정상입니다. 이 창은 터널이 유지되는 동안 닫지 않습니다.

### 터널 확인

4번 테스트 창에서 아래 명령을 실행합니다.

```powershell
curl.exe http://127.0.0.1:18001/v1/models
```

Qwen3 모델 정보가 나오면 터널 연결 성공입니다.

### 2단계 오류 확인

로컬 포트가 이미 사용 중인지 확인합니다.

```powershell
Get-NetTCPConnection -LocalPort 18001 -ErrorAction SilentlyContinue |
  Select-Object LocalAddress,LocalPort,State,OwningProcess
```

터널 창에 `bind: Address already in use`가 나오면 기존 터널이 남아 있을 수 있습니다. 먼저 기존 창을 찾아 `Ctrl+C`로 종료한 뒤 다시 실행합니다.

원격 서버의 8001 모델 서버가 정상인지 1번 창에서 다시 확인합니다.

```bash
curl http://127.0.0.1:8001/v1/models
```

## 3단계 — FastAPI RAG 프로젝트 실행

새 PowerShell 창에서 프로젝트 폴더로 이동합니다.

```powershell
cd "C:\Users\ydy00\OneDrive\Desktop\ai 프로젝트\260813_자료수집\Project1"
```

Furiosa 연결 환경변수를 설정합니다.

```powershell
$env:FURIOSA_BASE_URL="http://127.0.0.1:18001/v1"
$env:FURIOSA_MODEL="furiosa-ai/Qwen3-8B-FP8"
```

FastAPI를 실행합니다.

```powershell
uv run --with-requirements requirements.txt uvicorn app.api.main:app --reload --port 8002
```

정상 실행 시 다음 로그가 표시됩니다.

```text
Uvicorn running on http://127.0.0.1:8002
Application startup complete.
```

이 창은 닫지 않습니다.

### 3단계 오류 확인

```text
File not found: requirements.txt
```

프로젝트 폴더가 아닌 위치에서 실행한 경우입니다. 아래 명령부터 다시 실행합니다.

```powershell
cd "C:\Users\ydy00\OneDrive\Desktop\ai 프로젝트\260813_자료수집\Project1"
```

```text
Address already in use
```

8002 포트를 이미 다른 프로그램이 사용 중인 경우입니다.

```powershell
Get-NetTCPConnection -LocalPort 8002 -State Listen |
  Select-Object LocalPort,OwningProcess
```

기존 FastAPI 창이 있으면 그 창에서 `Ctrl+C`를 누른 뒤 다시 실행합니다. PID를 임의로 종료하지 말고, 해당 프로세스가 FastAPI인지 먼저 확인합니다.

## 4단계 — 연결 및 RAG 질문 테스트

새 PowerShell 창에서 Furiosa 터널을 먼저 확인합니다.

```powershell
curl.exe http://127.0.0.1:18001/v1/models
```

그다음 FastAPI 상태를 확인합니다.

```powershell
curl.exe http://127.0.0.1:8002/health
```

정상 결과에는 다음 항목이 포함되어야 합니다.

```json
{
  "status": "ok",
  "documents": 15,
  "furiosa_configured": true,
  "furiosa_model": "furiosa-ai/Qwen3-8B-FP8"
}
```

`furiosa_configured`가 보이지 않으면 예전 FastAPI 서버에 연결된 것입니다. 3단계 창에서 서버를 종료하고 환경변수를 다시 설정한 뒤 8002로 재실행합니다.

### 실제 문서 기반 질문 테스트

```powershell
$body = @{
  question = "Lam Research의 selective etch는 GAA에 어떻게 적용되는가?"
  top_k = 5
} | ConvertTo-Json -Compress

$result = Invoke-RestMethod `
  -Uri "http://127.0.0.1:8002/api/v1/query" `
  -Method Post `
  -ContentType "application/json" `
  -Body $body

$result | ConvertTo-Json -Depth 10
```

정상 응답에서 확인할 항목:

```json
"provider": "furiosa",
"model": "furiosa-ai/Qwen3-8B-FP8",
"retrieval": {
  "method": "bm25+tfidf-cosine"
}
```

### 브라우저 화면

상태 확인:

```text
http://127.0.0.1:8002/health
```

Swagger API 테스트:

```text
http://127.0.0.1:8002/docs
```

`POST /api/v1/query` → `Try it out` → 질문 JSON 입력 → `Execute` 순서로 실행합니다.

## 문제 발생 시 확인 순서

항상 아래 순서로 확인합니다.

```text
1. SSH 접속: ssh furiosa
2. 원격 모델: curl http://127.0.0.1:8001/v1/models
3. 로컬 터널: curl.exe http://127.0.0.1:18001/v1/models
4. FastAPI 상태: curl.exe http://127.0.0.1:8002/health
5. RAG 질문: /api/v1/query
```

앞 단계가 실패하면 다음 단계로 넘어가지 않습니다.

## 재접속 시 기억할 점

- 노트북을 끄면 SSH 접속과 터널은 다시 실행해야 합니다.
- 프로젝트 코드와 기록 파일은 노트북에 저장되어 사라지지 않습니다.
- `$env:FURIOSA_BASE_URL`과 `$env:FURIOSA_MODEL`은 PowerShell 창을 닫으면 사라지므로 3단계마다 다시 입력합니다.
- Furiosa 모델 파일은 원격 서버에 있으므로 노트북 저장공간과 별개입니다.
- 서버 로그의 `Uvicorn running ...` 문장은 입력하지 않고 화면에 표시되는 정상 상태 문구입니다.
