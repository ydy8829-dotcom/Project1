# 반도체 공정장비 Technical RAG Copilot 제출용 한국어 통합 기록

## 1. 프로젝트 목표

반도체 제조장비의 카탈로그·기술문서·서비스 문서를 검색하고, 모델명·약어·공정 용어가 포함된 질문에 문서 근거와 출처를 함께 제시하는 RAG 챗봇을 구축한다.

## 2. 현재까지 완료한 작업

- Applied Materials와 Lam Research의 반도체 공정·장비 공개 문서를 수집하고 메타데이터화했다.
- 문서 본문과 제목·회사·공정·제품·적용 분야·소자 구조·기술 키워드를 검색 인덱스에 반영했다.
- BM25와 TF-IDF cosine을 결합한 하이브리드 검색을 구현했다.
- 모델명·약어·동의어 정규화 모듈을 구현했다.
- FastAPI 질의응답 API를 구현했다.
- Furiosa NPU 서버의 `furiosa-ai/Qwen3-8B-FP8`을 SSH 터널로 연결했다.
- 검색 근거를 Qwen3 프롬프트에 주입하고 출처 URL을 포함하는 답변을 확인했다.
- 문서에 없는 식각 속도·처리량을 질문했을 때 임의의 수치를 생성하지 않는지 검증했다.
- 답변이 근거 부족을 명시하면 `insufficient_evidence=true`로 보정하도록 수정했다.
- 50문항 자동 평가셋과 Top-1·Top-3·MRR·nDCG@3 자동 집계를 구현했다.
- 선택적으로 Furiosa Qwen3 Reranker API를 연결할 수 있는 모듈을 추가했다.

## 3. 검증 환경

```text
Furiosa LLM 원격 서버: 8001
SSH 터널 로컬 포트: 18001
FastAPI RAG Gateway: 8002

검색: BM25 + TF-IDF cosine
검색 가중치: 키워드 0.55 / 의미 0.45
```

## 4. 확인된 결과

- `/v1/models`에서 Qwen3-8B-FP8 확인: 성공
- RAG 질의응답에서 `llm.provider=furiosa`: 성공
- 응답 종료 상태 `finish_reason=stop`: 정상
- 근거 부족 질문에서 임의의 처리량·식각 속도 생성 없음: 통과
- 회귀 테스트 4개 통과

## 5. 평가 결과와 한계

현재 50문항은 자동 생성 seed 데이터이며 도메인 전문가 검수 전이다.

```text
Top-1: 6%
Top-3/Recall@3: 38%
MRR: 0.2919
nDCG@3: 0.2406
목표: 검수된 평가셋 기준 Top-3 80% 이상
```

단일 정답 문서만 비교하는 방식은 최종 평가에 사용하지 않는다. 한 질문에 여러 문서가 답이 될 수 있고, 검색 순위만으로 답변의 사실성·인용 정확성을 판단할 수 없기 때문이다. 최종 평가에는 다중 관련 문서, relevance 등급, 기대 주장, 금지 주장, 근거 지원율, 인용 정확도, 환각률, 거부 정확도를 포함한다.

## 9. 임베딩·reranker 연결 진행

임베딩 클라이언트와 Furiosa Qwen3 reranker 클라이언트를 추가했다. 임베딩 서버가 설정되면 BM25와 임베딩 cosine을 결합하고, reranker 서버가 설정되면 후보 문서를 재정렬한다. 서버가 설정되지 않은 경우 기존 검색으로 자동 fallback한다. 실제 NPU 서버 기동 전에는 `furiosa-smi ps`로 현재 Qwen3 서버의 NPU 사용량을 확인한다.

2026-08-14 원격 확인 결과, Qwen3-8B-FP8 서버가 `npu0~npu7` 전체 코어를 사용 중이었다. 따라서 임베딩·reranker를 즉시 추가 기동하지 않고, NPU 장치 분할 가능성을 확인한 뒤 안전하게 검증한다.

임베딩 모델 `Qwen3-Embedding-0.6B`를 원격 8003에서 기동하고 로컬 18003 터널을 통해 `/v1/embeddings` 호출을 검증했다. 2개 입력에 대한 벡터 2개 반환에 성공했다.

FastAPI `/health`에서 `embedding_configured=true`, `embedding_model=furiosa-ai/Qwen3-Embedding-0.6B`를 확인했다. 임베딩 설정 연결은 완료되었고, 생성 모델과 reranker는 다음 단계에서 연결한다.

Reranker `Qwen3-Reranker-0.6B`도 원격 8004와 로컬 18004 터널로 연결했다. evidence에 `retriever=furiosa-reranker`, `rerank_score`가 표시되고 `Selective Etch Product Family`가 1위로 반환되는 것을 확인했다. 점수가 전반적으로 높아 변별력은 50문항 평가에서 추가 검증한다.

실제 FastAPI 질의에서 `retrieval.method=bm25+embedding-cosine`을 확인해 임베딩 검색 계층 연결을 완료했다. 생성 모델은 당시 자원 확보를 위해 중단된 상태였다.

## 10. 2026-08-14 NPU·GPU 생성 성능 비교 실측

### 측정 목적과 조건

NPU와 GPU의 순수 생성 성능을 비교하기 위해 RAG 검색·reranker는 제외하고 Qwen3-8B 계열 생성만 측정했다. 두 환경 모두 같은 5개 한국어 질문을 순환하고, 워밍업 2회 후 20회를 순차 실행했으며 `max_tokens=128`, temperature 0.1(결정적 생성)을 사용했다.

| 구분 | NPU | GPU |
|---|---|---|
| 실행 장치 | Furiosa NPU 원격 서버 | NVIDIA GeForce RTX 4060 8GiB 로컬 PC |
| 모델 | `furiosa-ai/Qwen3-8B-FP8` | `unsloth/Qwen3-8B-bnb-4bit` |
| 양자화 | FP8 | bitsandbytes NF4 4-bit |
| 실행 경로 | OpenAI 호환 `/v1/chat/completions` | PyTorch CUDA 직접 생성(토크나이저+생성 시간) |
| 반복/워밍업 | 20 / 2 | 20 / 2 |

### 검증 및 재현성

- GPU 환경: NVIDIA Driver 591.86, CUDA 12.8(PyTorch), RTX 4060 8GiB.
- GPU 벤치마크 20건 모두 완료 토큰을 생성했고, 피크 VRAM이 0보다 큰 것을 검사했다.
- 프로젝트 회귀 테스트는 GPU 작업 전후 모두 `5 passed`였다.
- 원시 GPU 결과는 `data/evaluation/qwen_gpu_benchmark.json`, 기존 NPU 기준값은 `data/evaluation/qwen_npu_benchmark.json`에 보관했다.
- 재현 명령: `\.venv\Scripts\python.exe scripts\benchmark_qwen_gpu.py --repeats 20 --warmup 2 --max-tokens 128`

### 해석 한계와 조치 기록

- 두 측정은 동일 Qwen3-8B 계열·동일 질문·동일 출력 토큰 제한을 사용했지만, NPU는 FP8이고 GPU는 4-bit NF4라 정밀도가 다르다. 또한 NPU는 HTTP API 종단간 시간, GPU는 로컬 PyTorch 호출 시간이다. 따라서 위 결과는 현재 장비·구성의 실측 비교이지 하드웨어 일반 우열 결론이 아니다.
- 최초 Ollama 0.32.11 GPU runner는 CUDA 장치 탐지에서 접근 위반(`0xc0000005`) 후 CPU fallback했다. 해당 CPU 결과는 GPU 성능표에서 제외했다.
- Microsoft Visual C++ 2015-2022 x64 재배포 패키지 갱신 후 CUDA PyTorch가 정상적으로 RTX 4060을 인식했고, 실제 GPU VRAM·사용률을 확인한 뒤 본 결과를 측정했다.

### 한계점

1. FP8과 NF4 4-bit는 정밀도·메모리 사용량이 다르므로 절대 성능의 하드웨어 우열을 단정할 수 없다.
2. GPU는 로컬 직접 호출이고 NPU는 HTTP API를 경유해, 통신·서버 오버헤드가 동일하지 않다.
3. 실제 완료 토큰 수가 요청마다 달라 평균 응답시간만으로 순수 생성 성능을 직접 비교하기 어렵다.
4. 동시성 1만 측정했으므로 다중 사용자 처리량·큐잉 지연·확장성은 평가하지 못했다.
5. 전력 데이터를 확보하지 못해 성능 대비 전력 효율(tokens/J)은 산출하지 않았다.

### 보완 계획

1. GPU에도 OpenAI 호환 서버를 구성해 NPU와 동일한 HTTP API·요청 형식으로 측정한다.
2. 동일 템플릿의 입력 토큰 배열과 고정 생성 토큰 수를 사용하고, TTFT·생성 시간·종단간 지연시간을 분리 기록한다.
3. `--concurrency` 인자를 추가해 동시성 1·2·4별 평균/P95 지연시간, req/s, tokens/s를 측정한다.
4. 가능하면 같은 양자화 정밀도로 재측정한다. 불가능하면 정밀도별 결과를 별도 표로 분리한다.
5. NPU는 `furiosa-smi` 반복 표본, GPU는 전력 텔레메트리를 제공하는 계측 수단으로 idle·load 평균/피크 전력을 측정한다.
